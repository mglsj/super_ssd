## Q2: Induction basics

*Mathematical Induction Basics [2 marks]*

Consider the following statements, where `ℕ` is the set of all natural numbers and `P` is a property of natural numbers (i.e., `P : ℕ → Prop`).

- S1: `P(0)`
- S2: `P(k) → P(k+1)`
- S3: `P(n)`
- S4: `∀n ∈ ℕ, P(n)`

Which of the following options are correct?

- A. Principle of mathematical induction helps us prove S3 by proving S1 and S2.
- B. Principle of mathematical induction helps us prove `(∀n ∈ ℕ, S3)` by proving S1 and S2.
- C. Principle of mathematical induction helps us prove S4 by proving S1 and `(∀k ∈ ℕ, S2)`.
- D. None of the above.

<Callout type="tip" title="Answer: C">
Induction concludes the universal statement S4 from the base case S1 and a step S2 that holds **for every** `k`. A and B use S2 for one unspecified `k` only, and A's conclusion S3 is not a universal statement.
</Callout>

<Fold title="Full explanation">

The key is to read S2 and S3 carefully. Neither contains a quantifier: `k` in S2 and `n` in S3 are **free variables**, names that are not bound by any `∀` or `∃`. A formula with a free variable is an *open* formula. On its own it is not a claim about all numbers, only about whichever number the name happens to stand for. The induction principle, by contrast, is a claim about all natural numbers, and its step premise must hold for *every* `k`:

<Rules>
  <Rule name="Induction" premises={["S1: P(0)", "∀k ∈ ℕ. S2"]} conclusion="S4: ∀n ∈ ℕ. P(n)" />
</Rules>

Read this as a chain: `P(0)` holds; the step with `k = 0` gives `P(1)`; the step with `k = 1` gives `P(2)`; and so on, so that every natural number is reached. The chain needs the step at *every* link, which is why the premise is `∀k ∈ ℕ. P(k) → P(k+1)`. That is exactly option C.

Options A and B both use S2 without the quantifier, so the step is known only for one particular `k`. That is not enough. To see this, take `P(n)` to be `n = 0`. Then `P(0)` is true. For `k = 5`, the step `P(5) → P(6)` is also true, because its left side `5 = 0` is false and an implication with a false left side holds. Yet `∀n. P(n)` is plainly false. So a base case plus a step for one `k` does not give the conclusion. Option A is wrong for a second reason as well: its conclusion S3 is an open formula, not the universal statement that induction establishes. Option B has the right conclusion but the wrong premise. Since C is correct, D is wrong.

The <a href={`${import.meta.env.BASE_URL}induction/`}>induction</a> page discusses this principle and its variants in full.

</Fold>

## Q3: Which Cons moves are legal?

*Hoare Logic Inference Rules [3 marks]*

Consider the following statements, where `{P}S{Q}` represents the Hoare triple used for specifying the partial correctness of program `S`.

- A. If `{P}S{Q}` and `Q → R` then `{P}S{R}`
- B. If `{P}S{Q}` and `R → P` then `{P}S{R}`
- C. If `{P}S{Q}` and `P → R` then `{R}S{Q}`
- D. If `{P}S{Q}` and `R → P` then `{R}S{Q}`
- E. If `{P}S{Q}` and `R → Q` then `{P}S{R}`
- F. If `{P}S₁{Q₁}`, `Q₁ → Q₂`, and `{Q₂}S₂{Q}` then `{P}S{Q}`, where `S = S₁; S₂`

Which of the above statements are correct?

<Callout type="tip" title="Answer: A, D, F">
The rule of consequence only allows **strengthening the precondition** (D: the new pre implies the old one) and **weakening the postcondition** (A: the old post implies the new one). F weakens the first half's postcondition to `Q₂` and then joins the halves with the sequence rule. B, C and E move in the wrong direction.
</Callout>

<Fold title="Full explanation">

Recall the rule of consequence from the <a href={`${import.meta.env.BASE_URL}hoare-logic/`}>Hoare logic</a> page:

```text
P ⇒ P′      {P′} S {Q′}      Q′ ⇒ Q
───────────────────────────────────  (Cons)
             {P} S {Q}
```

It allows two moves on a proved triple: **strengthen the precondition**, replacing it with a new precondition that *implies* the old one, and **weaken the postcondition**, replacing it with a new postcondition that is *implied by* the old one.

<Mermaid code={`flowchart LR
  Rp["R new pre"] ==>|"must imply"| P["P old pre"]
  P --> S["S"] --> Q["Q old post"]
  Q ==>|"must imply"| Rq["R new post"]`} />

Why these directions and not the others? Think of each assertion as the set of states that satisfy it. If `R → P`, every state in `R` is also in `P`, so `R` is the smaller set. The triple `{P} S {Q}` promises good behaviour from every state in `P`, so in particular from every state in the smaller set `R`. On the other side, if `Q → R`, then every final state in `Q` is also in `R`, so a program that always ends in `Q` always ends in `R`. The reverse moves would require `S` to behave well from states we know nothing about, or to land in a smaller set than we proved it lands in.

| | Legal? | Reason |
|---|---|---|
| A | yes | weakens the post: the old post implies the new one |
| B | no | the post is replaced by `R`, but nothing says `Q → R` |
| C | no | the new pre is implied by the old one: this weakens the pre |
| D | yes | strengthens the pre: the new pre implies the old one |
| E | no | the new post implies the old one: this strengthens the post |
| F | yes | Cons weakens the first post to `Q₂`, then Seq joins the halves |

Option B is a trap because its implication `R → P` is the right shape for strengthening a precondition, but it is used to change the *postcondition*, where it says nothing useful. Option F combines two rules:

<Rules>
  <Rule name="Cons" premises={["P ⇒ P", "{P} S₁ {Q₁}", "Q₁ ⇒ Q₂"]} conclusion="{P} S₁ {Q₂}" />
  <Rule name="Seq" premises={["{P} S₁ {Q₂}", "{Q₂} S₂ {Q}"]} conclusion="{P} S₁; S₂ {Q}" />
</Rules>

(The left premise `P ⇒ P` is trivially true: the precondition is left unchanged.)

To show that an option is *not* a valid rule, it is enough to give one instance where the premises hold and the conclusion fails. Writing these counterexamples earns partial credit:

- **C:** `{x = 1} y = x {y = 1}` is valid. Take `R ≡ True`, so `P → R` holds. The conclusion `{True} y = x {y = 1}` is false: start with `x = 2`.
- **E:** `{True} x = 5 {x > 0}` is valid. Take `R ≡ x > 10`, so `R → Q` holds. The conclusion `{True} x = 5 {x > 10}` is false.
- **B:** `{x = 1} y = 2 {y = 2}` is valid. Take `R ≡ x = 1 ∧ y = 7`, so `R → P` holds. The conclusion `{x = 1} y = 2 {x = 1 ∧ y = 7}` is false, because after the assignment `y` is 2.

</Fold>

## Q4: Swap verification

*Swap Program Verification [3 marks]*

Let `S` be the following sequential program to swap the values in the variables `x` and `y`:

```text
t := x;
x := y;
y := t;
```

Write the partial correctness specification for `S` using a Hoare triple and justify its correctness using the Axioms and Inference Rules for Hoare logic.

<Callout type="tip" title="Answer">

Specification, with ghost variables `X` and `Y` for the starting values: `{x = X ∧ y = Y} S {x = Y ∧ y = X}`.

Proof: apply the assignment rule three times from the bottom up, join with Seq, and reorder the first conjuncts with Cons.

</Callout>

<Proof lines={[
  { a: "{ x = X ∧ y = Y }" },
  { a: "⇔ { y = Y ∧ x = X }", j: "Cons: ∧ commutes" },
  { c: "t := x", j: "Assign: t ↦ x" },
  { a: "{ y = Y ∧ t = X }" },
  { c: "x := y", j: "Assign: x ↦ y" },
  { a: "{ x = Y ∧ t = X }" },
  { c: "y := t", j: "Assign: y ↦ t" },
  { a: "{ x = Y ∧ y = X }" },
]} />

<Fold title="Full explanation">

The first task is the specification. A postcondition such as `x = y ∧ y = x` would be useless, since it refers only to final values. We need **auxiliary** (ghost) variables `X` and `Y` that record the starting values. They appear only in assertions, never in the program, so the program cannot change them. In Python the program is `t = x; x = y; y = t`.

The proof uses the assignment rule `{Q[E/x]} x := E {Q}`, where `Q[E/x]` means `Q` with `E` substituted for every occurrence of `x`. The rule works backwards, so we start from the postcondition at the bottom and push it up through each assignment.

1. Before `y := t`, substitute `t` for `y` in `x = Y ∧ y = X`. This gives `x = Y ∧ t = X`.
2. Before `x := y`, substitute `y` for `x` in that. This gives `y = Y ∧ t = X`.
3. Before `t := x`, substitute `x` for `t`. This gives `y = Y ∧ x = X`.

The assertion we reach at the top, `y = Y ∧ x = X`, is the given precondition with its two conjuncts in the other order. Since `∧` is commutative, the two are logically equivalent, and the rule of consequence connects them. The sequence rule is used twice to join the three triples into one. ∎

The midconditions have a clear meaning, which is a useful check on the algebra. After `t := x`, `t` holds the old `x`. After `x := y`, `x` holds the old `y` while `t` still holds the old `x`. The last assignment copies the old `x` into `y`.

**Marking:** about +1 per correct midcondition: `{x = X, y = Y}`, `{y = Y, t = X}`, `{x = Y, t = X}` and the final `{x = Y, y = X}`.

</Fold>

## Q5: Factorial specification and invariant

*Factorial Program Verification [4 marks]*

Let `S` be the following factorial program:

```text
y := 1;
while (x != 0) {
    y := y * x;
    x := x - 1;
}
```

Write a partial correctness specification for `S` using a Hoare triple and justify its correctness using the Axioms and Inference Rules for Hoare logic. Your solution must include: (1) a suitable loop invariant, (2) proof of invariant initialization, (3) proof of invariant preservation, and (4) proof that invariant + loop condition implies the postcondition.

<Callout type="tip" title="Answer">

- **Specification:** `{x = X ∧ X ≥ 0} S {y = X!}`
- **Invariant:** `I ≡ y · x! = X! ∧ x ≥ 0` ("`y` is the product computed so far, `x!` is what remains").
- **Initialisation:** after `y := 1`, `1 · x! = X!` because `x = X`.
- **Preservation:** if `I` holds and `x ≠ 0`, then `x ≥ 1`, and `(y·x)·(x−1)! = y·x! = X!`.
- **Exit:** `x = 0` gives `y · 0! = y = X!`.

</Callout>

<Proof lines={[
  { a: "{ x = X ∧ X ≥ 0 }" },
  { a: "⇒ { 1 · x! = X! ∧ x ≥ 0 }", j: "Cons" },
  { c: "y := 1", j: "Assign" },
  { i: "{ I : y · x! = X! ∧ x ≥ 0 }", j: "(2) initialisation" },
  { c: "while (x != 0) {" },
  { a: "{ I ∧ x ≠ 0 }", indent: 1 },
  { a: "⇒ { (y·x) · (x−1)! = X! ∧ x−1 ≥ 0 }", indent: 1, j: "Cons: x ≥ 1, x·(x−1)! = x!" },
  { c: "y := y * x", indent: 1, j: "Assign" },
  { a: "{ y · (x−1)! = X! ∧ x−1 ≥ 0 }", indent: 1 },
  { c: "x := x - 1", indent: 1, j: "Assign" },
  { i: "{ I }", indent: 1, j: "(3) preservation" },
  { c: "}" },
  { a: "{ I ∧ x = 0 }", j: "While" },
  { a: "⇒ { y = X! }", j: "(4) Cons: 0! = 1" },
]} />

<Fold title="Full explanation">

### The specification

The program computes the factorial of the starting value of `x` into `y`. As in Q4, the starting value of `x` is destroyed (the loop counts it down to 0), so the postcondition must refer to it through an auxiliary variable `X`. Factorial is defined only on natural numbers, so the precondition must also say `X ≥ 0`. This is not a formality. If `x` starts negative, `x - 1` never reaches 0 and the loop runs forever. Under partial correctness that run would not violate the specification, but the invariant mentions `x!`, which only makes sense when `x ≥ 0`.

### Finding the invariant

Run the loop by hand, record the variables after each iteration, and look for a relationship that stays the same. Writing `X` for the starting value of `x`:

| iteration | `x` | `y` |
|---|---|---|
| 0 | `X` | `1` |
| 1 | `X − 1` | `1 · X` |
| 2 | `X − 2` | `1 · X · (X − 1)` |
| 3 | `X − 3` | `1 · X · (X − 1) · (X − 2)` |
| … | … | … |
| `X` | `0` | `1 · X · (X − 1) · … · 1` |

Reading across a row, `y` is the product of the factors already multiplied in, from `X` down to `x + 1`, and the factors still to come are `x, x − 1, …, 1`, whose product is `x!`. So the product of the two is always the whole factorial: `y · x! = X!`. The second conjunct `x ≥ 0` is needed so that `x!` is defined. (The teacher wrote the first conjunct as `x! · y = X!`, which is the same thing.) A run with `X = 4`:

| step | `x` | `y` | `y · x!` |
|---|---|---|---|
| start | 4 | 1 | 1 · 24 = 24 |
| 1 | 3 | 4 | 4 · 6 = 24 |
| 2 | 2 | 12 | 12 · 2 = 24 |
| 3 | 1 | 24 | 24 · 1 = 24 |
| exit | 0 | 24 | 24 · 1 = 24 |

### Initialisation

We must show `{x = X ∧ X ≥ 0} y := 1 {I}`. Working backwards, the assignment rule substitutes `1` for `y` in `I`, giving `1 · x! = X! ∧ x ≥ 0`. The given precondition implies this: `x = X` gives `x! = X!`, and `x = X ≥ 0` gives `x ≥ 0`. This is the pattern for every initialisation step: compute the substituted invariant backwards, then bridge to the given precondition with Cons.

### Preservation

We must show `{I ∧ x ≠ 0} y := y*x; x := x−1 {I}`. Through `x := x − 1`, substitute `x − 1` for `x` in `I`: this gives `y · (x−1)! = X! ∧ x−1 ≥ 0`. Through `y := y * x`, substitute `y · x` for `y`: this gives `(y·x) · (x−1)! = X! ∧ x−1 ≥ 0`.

We now need `I ∧ x ≠ 0` to imply that. Two facts do the work. First, `x ≥ 0` and `x ≠ 0` together give `x ≥ 1`, hence `x − 1 ≥ 0`. Second, for `x ≥ 1`, `x · (x−1)! = x!`, which is the defining equation of factorial. So `(y·x)·(x−1)! = y·x! = X!` by the invariant. This is exactly where the conjunct `x ≥ 0` and the loop test `x ≠ 0` are needed: without them `(x−1)!` would be undefined. The sequence rule joins the two assignments, and the while rule then gives `{I} while (x ≠ 0) {…} {I ∧ x = 0}`.

### Exit

When the loop stops, its test has failed, so `¬(x ≠ 0)`, that is `x = 0`. With the invariant, `y · 0! = X!`, and since `0! = 1` this is `y = X!`, the postcondition.

### Putting it together

<Mermaid code={`flowchart TB
  Pre["{x = X ∧ X ≥ 0}"] -->|"y := 1 · init"| I["{I}"]
  I --> B{"x ≠ 0 ?"}
  B -- "yes: {I ∧ x≠0}" --> Body["y := y*x; x := x−1"]
  Body -->|"preservation"| I
  B -- "no: {I ∧ x=0}" --> Post["exit ⇒ {y = X!}"]`} />

The sequence rule joins the initialisation triple to the while triple, and Cons with the exit implication turns `I ∧ x = 0` into `y = X!`. ∎

**Marking:** +1 invariant, +1 initialisation, +1 preservation, +1 exit. Name the rule (Assign, Seq, Cons, While) at every step.

</Fold>

<Fold title="Total correctness (not asked)">

The proof above is of partial correctness: *if* the loop stops, `y = X!`. To show that it does stop, use a **variant**, a natural-number quantity that strictly decreases on every iteration. Here `x` itself works: the invariant keeps `x ≥ 0`, and each iteration decreases `x` by 1, so the loop terminates whenever `X ≥ 0`. That upgrades the result to the total correctness triple `[x = X ∧ X ≥ 0] S [y = X!]`.

</Fold>

## Practice drills

**Drill 1.** What is the weakest precondition of `x := x + y; y := x − y` for the postcondition `{y = A}`?

<Fold title="Answer">

`x = A`. Work backwards: through `y := x − y`, substitute to get `x − y = A`; through `x := x + y`, substitute to get `(x + y) − y = A`, which simplifies to `x = A`.

</Fold>

**Drill 2.** Find an invariant for `i := 0; s := 0; while i < n: i := i+1; s := s + i` with postcondition `{s = n(n+1)/2}`, given `n ≥ 0`.

<Fold title="Answer">

`I ≡ s = i(i+1)/2 ∧ 0 ≤ i ≤ n`. Initialisation: `0 = 0·1/2`. Preservation: `s + (i+1) = i(i+1)/2 + (i+1) = (i+1)(i+2)/2`, and `i < n` gives `i + 1 ≤ n`. Exit: `i ≥ n ∧ i ≤ n ⇒ i = n`, so `s = n(n+1)/2`.

</Fold>

**Drill 3.** Is `{x > 0} x := x − 1 {x ≥ 0}` valid?

<Fold title="Answer">

Yes. The assignment rule gives `{x − 1 ≥ 0} x := x − 1 {x ≥ 0}`. Over the integers, `x > 0 ⇒ x ≥ 1 ⇒ x − 1 ≥ 0`, so Cons strengthens the precondition to `x > 0`.

</Fold>
